## 1. 기능 분류 (MoSCoW)

판단 기준은 하나다. **"편집 중 문서 카드를 넘기는 재미"를 시험하는 데 없으면 안 되는가.**

### 필수 (Must): 이것 없이는 출시하지 않는다
| 기능 | 이유 | 출처 |
|---|---|---|
| `sidebar.json` 30초 폴링 → 카드 큐 (네임스페이스 제외, 하위 문서는 상위 문서 카드로 올림, 중복·본 문서 제거) | 피드 원천 | 4, 4b |
| 카드 미리보기 서버 `/api/card?title=` (Cloudflare Workers, head만 읽어 og 3개 추출·정제, CDN 6시간 캐시) | `/w/`에 CORS가 없다 | 4, 4b |
| 카드 UI: 문서명, 정제한 요약, 대표 이미지, 라이브 라벨(N분 전 편집, 하위 문서 편집 중), 출처·라이선스 표기 | 핵심 가치 + CC BY-NC-SA 의무 | 4b |
| 세로 스와이프 (CSS scroll-snap) | 형식 자체 | 1, 4b |
| 원문 열기 (새 탭, 피드 위치 유지) | 원문으로 트래픽을 보내는 구조. 원문 클릭률은 성공 지표다 | 3, 4b |
| 제목만 있는 카드로 낮추기 (서버 한도 초과·차단 시) + 상태 배너 | 0원 조건 vs 바이럴 충돌 해소 | 4b |
| 이미지 보통·흐리게·끄기 전역 토글 + 성인 키워드 문서는 기본 흐림 | 편집 중 문서 40건 중 2건이 성인물 관련이었다. 공개 피드에서 필요한 최소 안전장치 | 4b, 6 |
| 익명 측정: Cloudflare Web Analytics + 세션 끝 비콘 1건(재방문 여부, 공유 유입 여부, 본 카드 수, 원문 클릭 수) → Workers Analytics Engine | 성공 지표를 잴 수단이 없으면 포트폴리오 숫자가 없다 | 5 |
| About 한 장: 비공식 서비스, 데이터 출처, 수집하지 않는 것, 운영사 요청 시 중단 | 운영사·사용자에 대한 최소 고지 | 4 |

### 권장 (Should): 일정이 되면 넣는다 (6일차까지)
| 기능 | 이유 |
|---|---|
| 공유: 그 카드부터 시작하는 링크(`/c/<문서명>`) + 카톡·X 미리보기(og 태그를 넣은 HTML을 Worker가 돌려줌) | 5단계 GTM의 유입 장치이고 "공유 유입" 지표의 전제다 |
| 좋아요 (localStorage) + 좋아요 목록 | 프로토타입에 있던 행동 신호. 만들기 쉽다 |
| 카드 섞기 규칙: 같은 접두어·같은 시각 묶음이 연달아 나오지 않게 간격 두기 | 한 편집자의 가나다순 묶음 편집이 70건 중 9건이었다 (6단계 관찰) |
| 요약 정제 추가 패턴: 영상 캡션, 인용문, 조사 앞 공백 | 6단계 관찰 |

### 선택 (Could): 출시 뒤 반응을 보고
| 기능 | 이유 |
|---|---|
| 랜덤 탭 (세션 제목 풀 + 시드 목록, "진짜 랜덤"은 namu.wiki로 연결) | 4b에서는 보조 탭으로 넣었지만, 1주 안에서는 편집 피드 본체가 먼저다. 큐가 빌 때는 "새 편집을 기다리는 중" 화면으로 충분하다 |

## 2. 핵심 사용자 흐름

1. 커뮤니티 글이나 공유 링크로 들어온다. 공유 링크면 그 카드가, 아니면 가장 최근 편집 카드가 첫 장이다. 첫 방문에는 한 줄 안내가 뜬다.
2. 카드에서 문서명, 요약, 이미지, "3분 전 편집" 라벨을 본다. **여기서 핵심 가치(지금 누군가 손대는 문서를 고르는 수고 없이 본다)를 얻는다.**
3. 위로 넘긴다. 30초마다 새 편집이 큐에 들어온다.
4. 궁금한 카드는 탭해서 원문을 새 탭으로 연다. 돌아오면 같은 자리다.
5. (권장) 좋아요를 누르거나 링크를 공유한다.
6. 서버가 막히면 제목만 있는 카드로 계속 넘긴다.

## 3. 성공 지표 (출시 2주)

| 지표 | 목표 | 재는 법 |
|---|---|---|
| 방문 | 500 | Cloudflare Web Analytics |
| 재방문 비율 | 15% 이상 | 세션 비콘의 재방문 플래그 |
| 원문 클릭이 있는 세션 비율 | 20% 이상 | 세션 비콘의 원문 클릭 수 |

- **중단 신호**: 재방문 비율 5% 미만이면 v1.1에 투자하지 않고 회고 글로 마무리한다.
- 숫자는 판단 기준이고 예측이 아니다 (5단계 반대 의견 5).

## 4. 명시적으로 만들지 않는 것
- **본문 뷰어**: 본문은 원문에서 읽는다. namutok은 발견까지만 한다.
- **계정, 서버 저장, 개인화**: 0원과 무수집을 지킨다.
- **광고, 후원, 결제**: CC BY-NC-SA 비영리 조건.
- **나무위키 편집·토론으로 유도하는 기능**: 커뮤니티 규정상 외부 개입으로 보일 수 있다.
- **"왜 편집되는지" 해설**: 실검 API가 막혔다. 라이브 라벨로 대신한다.

## 5. 설계로 넘길 열린 질문
1. 스택: Vite + React 정적 빌드인가, Next.js 정적 내보내기인가 (사용자 조건은 React 계열 웹·PWA)
2. Workers CPU 10ms 안에 `/w/` head만 읽고 끊을 수 있는가 (스트림을 읽다가 `</head>`에서 중단)
3. 카드 미리보기 캐시 키와 실패 캐시(차단 페이지를 6시간 캐시하지 않기)
4. 성인 키워드 목록의 범위와 오탐 처리
5. 측정 비콘 스키마 (식별자 없이 재방문을 어떻게 표시할지)

## 반대 의견

1. **재미가 검증되지 않은 채 1주를 쓴다.** 6단계를 건너뛰어 A4는 카드 재료 품질만 확인된 상태다. 출시 후 재방문이 5% 미만이면 1주가 회고 글 하나로 끝난다. 개발 첫 이틀 안에 프로토타입 링크라도 지인 3명에게 보내면 이 위험이 크게 줄어든다.
2. **필수가 9개라 1주가 빠듯하다.** 특히 측정 비콘, 이미지 토글, 제목만 있는 카드 폴백은 "핵심 가치"가 아니라 운영·안전 장치다. 일정이 밀리면 공유(권장)가 먼저 빠지는데, 그러면 5단계 GTM의 유입 장치와 공유 지표가 함께 사라진다.
3. **랜덤 탭을 선택으로 내린 것은 4b와 다르다.** 편집 피드가 밤에 느려지거나 단조로우면 대체 콘텐츠가 없다. 다만 큐가 빌 일은 적다(분당 약 25건 편집, 4단계 실측).
