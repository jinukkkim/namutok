### namutok 대비 약점 / 기회
- **가장 가까운 잠재 경쟁 기능은 홈의 "연관 문서" 이미지 카드 캐러셀**이다(신규 확인). umanle가 이를 세로 피드로 키우면 namutok의 포맷 차별점은 사라진다. 반면 지금은 홈 하단의 가로 캐러셀일 뿐이고, 소스는 "실시간 편집"이 아니다.
- 랜덤을 내비게이션 자리에 넣었다가 반발을 산 선례가 있다. namutok은 랜덤을 별도 탭으로 두고 **"피드 위치를 지키는 뒤로 가기"**를 보장해야 한다. iOS 리뷰 69건 중 47건이 뒤로가기 불만이다.
- 실검 썸네일을 강제로 노출하는 데 대한 반감이 크다. **이미지 흐림·끄기 토글**을 출시 조건으로 둔다.
- iPad를 지원하지 않고, Android 1.7★에 개발자 답변은 0건이다. 그래서 대체재를 찾는 유입이 존재한다("크롬으로", "나무뷰어로 감"). PWA인 namutok은 iPad와 데스크톱에서도 바로 동작하는 점을 내세울 수 있다.
- 광고 기반이고 데이터 삭제가 불가능하다(Play 표기). namutok은 무광고와 무수집을 신뢰 요소로 쓸 수 있다. 단, 원문 트래픽은 umanle 광고로 보낸다.

### 실제 기능 흐름
1. 앱을 열면 나무위키 대문이 웹뷰로 뜬다. 상단 바에는 뒤로/앞으로 화살표, 문서 제목, 새로고침이 있다 [원문 확인 — 스크린샷 1].
2. 하단 플로팅 버튼(즐겨찾기 별, 목차, 검색, 목록, 더 보기)으로 즐겨찾기, 목차 점프, 검색을 한다 [원문 확인 — 스크린샷 1, 스토어 설명].
3. 링크를 길게 누르면 미리보기와 공유가 뜬다(2.1.1, 2022-01-04). 홈 화면 아이콘을 길게 누르면 **랜덤 문서로 바로 간다** [원문 확인 — 버전 기록, 설명].
4. 설정 > 앱 설정 > **데이터 업데이트**: 사이트 구조가 바뀌어 즐겨찾기나 검색 버튼이 고장 나면 앱 업데이트 없이 셀렉터 데이터를 받아 고친다(2.3, 2026-06-02) **[신규]** [원문 확인 — 버전 기록].
5. 테마/다크 모드, 블루투스 키보드 단축키, URL Scheme, iCloud 동기화(즐겨찾기·방문 기록)를 지원한다. 사이트 광고 차단을 내세우지만 2024년 이후 여러 번 무력화됐다(기존).

4. **View Trending Searches**: `search.namu.wiki/api/ranking` 배열을 순위 목록으로 보여 준다 [원문 확인 — `src/trending-searches.tsx`].

### namutok 대비 약점 / 기회
- **36MB 선다운로드와 덤프 기반 신선도(2026-02-06에서 멈춤)**가 구조적 약점이다. namutok은 sidebar.json으로 "몇 분 전 편집"을 보여 주므로 정반대 축(신선도)에서 이긴다.
- 영어 Simple Wikipedia 한정이고 다국어는 미정이다. 한국어 콘텐츠 경쟁자가 아니다.
- 로컬 점수제 추천은 "3시간 스크롤", "잡지 같다"는 헤비 유저를 만들었지만 "관심 없는 관련 문서"와 "랜덤 같다"는 반대 반응도 있다. namutok이 경량 개인화를 넣는다면 **좋아요를 유도하는 UI**(점수가 좋아요에 크게 의존)와 수동 관심사 편집(요청 #21)이 필요하다.
- NSFW 필터를 카테고리로 구현하려다 실패했다(PR #31). 나무위키는 분류 체계가 더 촘촘하지만, 성인·사건사고 분류의 커버리지를 미리 검증해야 한다.
- AGPL-3.0이라 코드를 가져다 쓰면 namutok도 공개 의무가 생긴다. 알고리즘 아이디어만 참고한다.
