# namutok (나무위키 × WikiTok)
- 현재 단계: 구현 착수. 리포 https://github.com/jinukkkim/namutok (public) 생성, 기획 문서는 `docs/planning/`으로 이동. 구현 계획 `docs/superpowers/plans/2026-11-18-namutok-mvp.md` Task 1(A10 차단 테스트)부터 이 세션에서 직접 진행
- 6단계 실험 프로토타입: https://claude.ai/artifact/DbEFEHrBziw6pcWN3VhcXy (원본 `prototype/`)
- 3단계 결과 페이지: https://claude.ai/artifact/UppoUwvg2YoCVNGMo9fNDA (원본 `03-competition.md`)
- 목적: 포트폴리오 + 실사용자 유치
- 제약: 1주 내 출시 / 운영비 0원(무료 티어만, 광고·결제 없음) / 웹·PWA (React/Next.js)
- 첫 타깃: 나무위키 헤비 유저
- Kill 기준: 나무위키 원문 실시간 확보가 막히면(기술 또는 약관) 접는다
- 선택된 해결책: 후보 2 — 화제(실시간 편집) 피드 (`/sidebar.json` 기반). 랜덤 탭(후보 1)은 보조 탭. 콘셉트 기준 문서는 `04b-concept.md`

## 메모 (다음 단계로 넘길 것)
- 3단계 완료: 직접 경쟁 없음(신뢰도 상). 해자는 약함(포맷·데이터 공개). 최대 위협은 운영사 접근 정책·재무. 이름 namutok은 도메인·상표 모두 비어 있음.
- 후보 2(화제 문서 피드)가 `/sidebar.json` 덕분에 기술적으로 가장 싸졌다. 게이트 1에서 후보를 비교할 때 반영한다.
- 6단계 준비 관찰: 편집 중 문서에는 한 편집자의 가나다순 묶음 편집(70건 중 9건)과 성인물 관련 문서(40건 중 2건)가 섞인다. 7단계 카드 섞기 규칙과 이미지 토글의 근거.
- 5단계 완료: 수익 없음. 채널 순서는 지인 → GeekNews·X·스레드 → (허락 시) 디시 나무위키 갤·실검챈. 게이트 2에서 볼 것은 A13(매니저 허락), 홍보와 차단의 연동, A4(재미) 미검증.
